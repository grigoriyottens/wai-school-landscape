Архитектура работы над проектом wai-school

Предложение для validation

Контекст — почему не Drive-only (твой первый вариант)

Логика Drive+MCP для документов — рабочая. Но у нас охват будет шире: лендинги (Next.js → Vercel), интерактивные квизы, Expo mobile app. Vercel auto-deploy и EAS builds требуют git remote; ревью кода и PR невозможны без git. Drive подходит для inbox, но не покрывает прод-код. Если упускаю что-то — поправь.

Предложение: GitHub org + multi-repo, Drive в роли inbox

  • GitHub Organization wai-school (private) — оба admins
  • wai-school/knowledge-base — текущий репо (wiki, decisions, MVP.canvas, CLAUDE.md)
  • wai-school/landings / quiz-app / mobile-app — добавляем по мере нужды
  • Drive shared folder wai-school-inbox для голосовых заметок / фоток / вложений с телефона
  • MCP-стек на запуске: GitHub MCP + Linear MCP (уже работает) + Drive MCP (сразу — твой воркфлоу может включать сценарии которые я не учёл)

Структура knowledge-base — что внутри репо

Чтобы было понятно про что речь — короткое описание ключевых папок и файлов внутри knowledge-base репо:

  • wiki/ — компилированная база знаний: страницы по трекам обучения, педагогике, позиционированию, оферингам. Каждая страница ссылается на источники в raw/ и на другие wiki-страницы. Точка входа в смысл продукта.
  • decisions.md — append-only лента founder-решений (продукт, педагогика, позиционирование, цена, операции) с явной атрибуцией (Made by: grisha | mik | grisha+mik). Источник истины — если raw-источник противоречит активному решению, побеждает запись здесь.
  • MVP.canvas — Obsidian canvas, визуальный service blueprint warm-funnel: belief-clusters покупательского момента, воронка от ПОЛУЧИЛ СООБЩЕНИЕ до ОПЛАТА, production-слой artefactов с тегами #артефакт / #информация. То что мы делали последние две недели.
  • deliverables/ — готовые артефакты для аудитории: marketing/ (лендинги, питчи), teaching/ (lesson scripts, mentor training), parent-facing/ (FAQ, onboarding), reports/ (lint, NPS, ретро).
  • raw/ — immutable исходники: team-notes/ (заметки founder'ов и mentor'ов), market/ (research), expert-interviews/, library/ (книги, статьи, tool docs), family-feedback/ (parent + student голос).
  • raw/_inbox/ — drop-zone для любых входящих файлов: голосовые memo, фотки whiteboards, PDF, URLs. По команде «process the inbox» Claude routит файлы в правильные content-папки и архивирует оригиналы. Drive shared folder wai-school-inbox (наш telephone drop-zone) sync'ится сюда — пишешь voice memo с iPhone → файл попадает в raw/_inbox/ → обрабатываем при следующей session.
  • CLAUDE.md — schema layer: правила для AI-агентов (Claude Code) как работать с этим knowledge-base, naming conventions, non-negotiable rules (immutability raw, anonymization детей, AI safety, attribution policy и т.д.).
  • scripts/ — хелперы (canvas validator + render PNG, intake processing).

Доступ с телефона

Anthropic в феврале 2026 выпустила Claude Code on web (claude.ai/code) + iOS app + Remote Control — основной путь push'а с телефона через Claude mobile, запасной — Working Copy ($20 разово) для прямых git-правок.

Решения с моей логикой (готов пересмотреть любое)

Решение Рекомендация Почему
Структура репо Multi-repo Гранулярный доступ когда придут фрилансеры + чувствительный материал в knowledge-base
Branch protection Self-merge OK на knowledge-base, ревью обязательно для кода Скорость на доках, безопасность на проде
Mobile git client Working Copy Стандарт индустрии 2026, нативная интеграция с Obsidian Mobile
Существующая git-история Сохранить как initial push Аудит-trail для decisions + твой onboarding tool
Имя репо knowledge-base Терминология Karpathy LLM Wiki, соответствует scope'у
Структура Linear Один project + labels per repo Соответствует текущему масштабу, не overengineer

Откуда взято

Архитектура соответствует Karpathy's LLM Wiki pattern (apr 2026) + проверена через Grok-search по 2026 founder-tweets: 6 из 8 indie-команд используют multi-repo git, 5 из 7 — эту MCP-комбинацию (GitHub + Linear + Drive + custom). Скопировал проверенный setup от практиков, не выдумывал.

Obsidian + canvas работают как сейчас

Любой git-tracked folder открывается в Obsidian как vault. Canvas (JSON) sync'ится через git как файл. Async — pull → обновлённый canvas открывается у тебя.

Что мы получаем — возможности по элементам сетапа

Совместная работа над знаниями

  • Оба правим в Obsidian локально, sync через git pull
  • decisions.md как append-only ledger с явной атрибуцией каждой записи (Made by: grisha | mik | grisha+mik)
  • Эволюция canvas в git-истории — видно reasoning за решениями

Production code и deploy

  • Push на main → автоматический live deploy за ~30 сек (Vercel) для лендингов и квизов
  • Mobile builds → TestFlight за 10–15 мин (EAS)
  • PR-based ревью прод-кода от другого co-founder'а
  • @claude в GitHub issue/PR через Claude Code GitHub Action → автоматический PR с фиксом

Доступ с телефона

  • Push фич на лендинг с iPhone через Claude Code on web (Mik отправляет правки из любой точки)
  • Drop voice memo / фотку в Drive → автосинк → Claude через Drive MCP читает inbox
  • Edit md / canvas в Obsidian Mobile поверх Working Copy folder

AI-оркестрация через MCP

  • «Создай задачу в Linear на основе этого decision'а» — Linear MCP
  • «Открой PR в landings с этим фиксом» — GitHub MCP
  • «Транскрибируй последнюю голосовую из inbox» — Drive MCP

Backup и аудит

  • Каждый clone = полная история. Три независимые копии (Grisha + Mik + GitHub) — потеря одной не критична
  • Git commits = audit trail кто что когда менял

Онбординг будущих участников

  • Фрилансер на лендинге → доступ только к landings репо, не видит partnership-conditions / decisions
  • Ментор на curriculum → доступ только к knowledge-base
  • Newcomer читает CLAUDE.md + последние commits = контекст за 30 минут
